# FluxForge feature validation matrix

This matrix is the inventory for the first-four handoff. Every maintained feature must have a named test or an explicit blocked receipt. A feature marked “covered” means the software contract was exercised; it does not imply physical experimental acceptance. Real INL validation additionally requires bound calibration, timing, response, nuclear-data, covariance, and source-provenance evidence.

## Required execution rule

Run the applicable tests for every row before promoting a goal. Record the command, environment, commit, result, skips, and known limitations in the corresponding receipt. If a feature has no test, add a bounded test or mark the feature explicitly blocked; do not infer coverage from neighboring features or from the CLI catalog alone.

The matrix intentionally distinguishes software coverage from INL acceptance. INL-specific claims require real-data receipts for each applicable workflow, source hashes, bound detector/geometry/timing metadata, and the scientific acceptance gates in `SCIENTIFIC_VALIDATION_20260916.md`.
