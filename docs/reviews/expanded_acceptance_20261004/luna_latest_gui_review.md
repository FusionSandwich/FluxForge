# Latest Qt GUI update review

Read-only review of the four commits on `origin/codex/qt-gui-review-20261004` (`581498f`, `b6315a5`, `67eab92`, `c5eee22`) and the first commit as staged in the integration checkout. The remaining three commit diffs were inspected directly. The checkout was mid-cherry-pick when reviewed. Parent reports targeted tests are running; I did not run GUI tests or modify source.

No concrete wrong-acquisition, callback, or report-field regression found. The calibration dialog now opens from the active `WorkspaceDocument` spectrum and captures document ID, spectrum ID, and its counts-array identity. Changing the active selection leaves the dialog bound to the original spectrum; replacing the document or replacing the acquisition under the same ID makes apply return false. The dialog only publishes its selection after an accepted apply, and the main-window instance disables that publication. Calibration is applied through the existing leaf undo command, preserving unrelated document fields, and the old active file-label rewrite is removed. Tests cover selection switch, same-ID reload/replacement, rejection without undo entries, apply/undo/redo, unchanged selection and active file label.

The callback contract remains backward compatible for callbacks returning `None`; only the literal `False` rejects. This is appropriate for the current main-window callback, which returns a bool. Layout commits keep calibration actions outside the scrollable plot/control regions, split mode/theme controls over rows, and move canvas controls to a second metadata row. Their narrow/laptop viewport tests are present and the CI job now includes the acquisition-target regression module.

One residual robustness edge is that stale-target validation compares counts-array identity, not a snapshot/revision of the array contents or calibration/profile inputs. The canonical document wrapper is frozen, but `GammaSpectrum` and its NumPy arrays are mutable; an in-place mutation could evade the guard. I found no in-place GUI/core count mutation path in this checkout, so this is not a current blocker. If such mutation is introduced, use an immutable array or captured content/revision fingerprint.
