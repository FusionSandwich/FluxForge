# Full independent RAFM North/South comparison

`full_campaign_comparison.json` compares two local `run_rafm_validation` passes on the historical portable engine based on `e5b8621` plus the South scenario changes in PR #230. It does not evaluate the current `4615e61` engine; a separate paired campaign on that engine is underway. Both historical-engine passes used the same 30 original ASC spectra (29 paired QG reports), `iec_tiered` counting for monitor and generic targeted lines, and the maintained legacy efficiency profile. North uses the historical ASC background; South uses the hash-bound native ANS background. Both passes completed, and the common QG report rows were checked for identity. This is a branch-specific background sensitivity experiment, not a selection or validation of a physically correct background.

On that historical engine, among 82 activity rows with a detected nuclide and calculable QG relative error in both passes, median absolute relative error is 42.0122% with North and 42.0121% with South. South improves 43 rows and worsens 39. Both full workflows fail thresholds on the same 25 samples. An Fe-59 row in RAFM3-A at 4 days is detected only with South; QG prints zero activity there, so that row has no finite relative-error comparison. See the complete per-isotope table and the largest net-count changes in the JSON.

The largest relative activity changes include RAFM3-N 24-hour Mn-56 (297.85 to 198.22 Bq, QG 314.87 Bq), RAFM3-N 300-second Al-28 (3342.49 to 3981.35 Bq, QG 555888 Bq), and RAFM3-A 4-day Cr-51 (3519.53 to 3231.94 Bq, QG 2090.5 Bq). South changes some lines materially but does not resolve broad raw/QG parity. For Co-Cd Co-60 under the common legacy efficiency, North gives 248.66 Bq and South 239.53 Bq against QG 234.95 Bq. The separate monitor receipt uses a recovered working South efficiency and therefore has different absolute activities; do not combine those estimates.

The QG background source and count-start/activity timing convention are unharmonized, and the South acquisition is later than some samples (#229). This historical engine interpolates channel counts for unequal energy grids; current engine `4615e61` uses integrated bin overlap with propagated covariance. Issue #228 tracks the old portable branch's integration risk. The executing NumPy 2.5.1 is outside the project's declared `<2.0` range. The South run began before a guard rejecting invalid override timing was added; the North run began after it. That guard accepts the pinned South timing and does not change the historical engine's numerical path. Both historical workflows produced diagnostic GLS/GRAVEL/MLEM outputs, with all three marked nonconverged and not admitted for physical flux inference. Two source counts lack original ASC; one raw count lacks a QG report (#231).
